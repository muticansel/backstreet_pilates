# Development workflow

- Read README.md, docs/BLUEPRINT.md, and docs/PROGRESS.md before continuing.
- Keep the code simple and explain changes using the relevant page review document.
- Work on one page at a time during subsequent iterations so the user can review all code.
- Do not mark a page approved without the user's explicit review.
- Update docs/PROGRESS.md with changes, decisions, verification, and the next review step.
- Keep authentication clearly labeled as a demo until a backend is selected and implemented.
- Never persist or log passwords.
- Run dart format, flutter analyze, and flutter test when Flutter is available; report limitations honestly.
